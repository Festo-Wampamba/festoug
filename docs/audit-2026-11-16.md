10. **Admin inquiry/payment panels ignore failed requests** — `inquiry-payment-panel.tsx:46-89`, `update-inquiry-status.tsx:20-25`. No `res.ok` check → UI shows payment state DB doesn't have.
11. **Chat endpoint cost abuse** — `src/app/api/chat/route.ts`: anonymous, no per-message size cap, client `system` role passes through, limiter is in-memory + spoofable `x-real-ip`. Cap size, strip non-user roles, require session or tighter guest limit.

## better-auth → Zitadel migration

### What exists today
- Server: 39 files call `auth()` from `src/lib/auth.ts` — a shim returning `{user:{id,role,accountStatus,emailVerified,...}}`. **Keep its shape and those 39 files don't change.**
- Gate: `src/proxy.ts` (role / banned / suspended / unverified).
- Custom UI that goes away: signin, signup, verify-email, forgot-password, reset-password, settings password form, OTP emails in `lib/email.ts`.
- DB: `user.id` is **uuid** with **13 FKs** to it. Zitadel `sub` is a numeric-string snowflake, not uuid.
- Data: existing users have **bcrypt** hashes; Google/GitHub linked accounts.
- App-owned state: `role`, `accountStatus` (ACTIVE/SUSPENDED/BANNED), `banned_email` table.

### Recommended approach
1. **Keep local `user` table + uuid PK; add `zitadel_sub text unique`.** No FK rewrites. Link on first login by `sub`, fall back to verified email.
2. **Integration — decision needed:**
   - **A. Better Auth `genericOAuth` plugin, Zitadel as sole provider** *(smallest diff)*: keeps sessions, adapter, shim, proxy. Delete email/password, OTP, social config.
   - **B. Drop Better Auth; `openid-client` / Zitadel Next.js example directly** *(fewer deps, more code)*: you own session cookies, refresh, logout.
   - Avoid Auth.js (`next-auth` v5 still beta, CVE history).
3. **Roles:** Zitadel project roles `admin`, `customer`; read `urn:zitadel:iam:org:project:roles` claim → shim's `role`. Keep DB mirror.
4. **Ban/suspend:** BANNED → deactivate in Zitadel + local `accountStatus` for live sessions. SUSPENDED (read-only) stays app-side.
5. **User import:** Zitadel import API accepts bcrypt hashes → no forced resets. Social users re-link via Zitadel IdPs.
6. **Cutover:** flag the login path, import users, run one release, then drop `session`, `account`, `verification`, `rateLimit`, `password_reset_token`.
